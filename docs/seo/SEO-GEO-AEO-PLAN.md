## 2. Evidence separation (hard rule)
- **Verified evidence:** only items in `content/testimonials.json` with `verified:true` and `consent:true` (currently none), plus claims with documents on file.
- **Illustrative (labelled on page):** 60 scenarios, 8+3 academy simulation case studies, 50-use-case library.
- **Synthetic drafts:** stay in `docs/` / internal only. Never rendered, never in schema (no Review/AggregateRating).
- Keep the three in separate files and separate page templates; the build must fail if a synthetic ID appears in `_site`.

## 3. Audit of existing site and deploy workflow
- Static site generated by `src/build.py` (Python), 134 pages, validator checks titles/descriptions/H1, JSON-LD, broken links, orphans.
- Deploy: Vercel builds on push to `main` (`vercel.json`, SITE_BASE pinned to the vercel.app URL until DNS cutover). **A push to main is a production release.** Only `main` should be pushed after approval.
- Already covers all 8 aspects: `/adobe-experience-platform/{architecture,data-ingestion,datasets,xdm-schemas,identity-service,real-time-customer-profile,segmentation-audiences,activation-destinations,implementation-guide,career-path,interview-questions}`, 20 guides, 8 stack pages, 8 topic hubs.
- Gaps: canonical still the vercel.app host (DNS pending); no Search Console/Bing verified; GTM absent; no per-page `dateModified` evidence; thin pages flagged in admin dashboard should be reviewed.
- Risk: mass pages from the CSVs = doorway/near-duplicate content. Not recommended.

## 4. Prioritised phased plan
**Phase 0 (blockers, user-side):** DNS cutover + canonical domain decision (`infiante360techacademy.com` vs `techacademy.infinate360.in`), Search Console + Bing verification, GTM ID, GitHub OAuth for admin.
**Phase 1 (≈2 wks): consolidate, no new URLs.** Map the 278 stems to existing aspect pages; add modifier sections (checklist, template, roadmap, FAQ, interview questions) to the 8 aspect pages; add concise 40–80 word answers; Last-reviewed dates only after real review; internal links among aspect pages and Academy.
**Phase 2: new pages, max ~15–20 expert-reviewed.** Candidates from the 50 briefs: AEP vs RTCDP (exists), CJA vs Adobe Analytics (exists), XDM design checklist, dataset-missing-in-CJA troubleshooting, Web SDK validation, AJO prerequisites, MCP safety. Each needs distinct diagram/code/checklist and primary-source citations.
**Phase 3: Academy.** Courses/curriculum/price/refund pages with `Course` schema only when real data exists. Career modifiers (salary/jobs) as one honest career hub, no salary figures without source.
**Phase 4: location/industry.** Only where there is genuine content (e.g. a real engagement or real regulatory context). Otherwise single "regions served remotely" section; no country × industry grid, no office claims.
**Phase 5: measurement.** GSC/Bing per domain, non-brand impressions, indexed-vs-submitted, qualified leads, sampled AI citations. No rank or citation promises.
GEO/AEO: crawlable HTML answers, `llms.txt` (exists), robots decision on OAI-SearchBot vs GPTBot (needs your policy choice), author/entity pages, consistent sameAs.

## 6. Staging strategy
1. Work only on `plan/seo-geo-aeo` or feature branches; Vercel creates a Preview URL per branch (not production). Set `X-Robots-Tag: noindex` on previews.
2. Pilot batch ≤10 pages per release; crawl preview with a crawler; fix; then request approval.
3. After approval: merge to `main`; verify live (status, canonical, sitemap, schema); submit sitemap; monitor GSC for 2 weeks before next batch.

## 7. Rollback plan
- Tag before each release: `git tag pre-release-YYYYMMDD`.
- Rollback = `git revert <merge>` and push to `main` (Vercel redeploys), or promote the previous deployment in Vercel (instant).
- Removed URLs: return 410/301 as appropriate; drop from sitemap in the same release.
- Keep `content/` data changes in separate commits so a content rollback does not undo code fixes.
